## 2026-10-16 — H8 PIN lock + fingerprint spike
- **Qué:** mandatory 4-digit PIN (created twice on the first launch after this deploy, asked on every cold open and after ≥60 s in the background), 5 failures → 30 s wait (doubling every 5, cap 15 min, persisted), "Olvidé mi PIN" (confirm → only the lock is removed, data kept, a new PIN is asked), content covered the instant the page goes to the background, and a "Seguridad" card at the bottom of Inicio with "Activar huella" (WebAuthn platform authenticator, PIN stays the fallback).
- **Por qué:** spec H8 / AC8 / eval 11 and decisions 2 + 6. Piero's calls (2026-10-16): mandatory from the first launch; forgot-PIN removes only the PIN (not the data); 4 digits with a wait after 5 failures.
- **Cómo:** `domain/pin.ts` (PBKDF2-SHA256 150k iterations + random salt, constant-time compare, `lockoutMs`, `shouldRelock`), `db/lock.ts` (state none/set/corrupt, `tryUnlock` serialized, `clearPin`), `LockGate` wraps the routes (the update banner stays outside). Fail closed: a damaged PIN row is "corrupt" (locked, only Forgot works), never "no PIN"; a failing read locks. A cold open mounts nothing from the app until the PIN passes; after a re-lock the screen state is kept but `hidden`, so a half-typed amount survives (Playwright: S/ 75 typed, 90 s away, PIN, still S/ 75). A clock moved backwards while away also re-locks.
- **Review fixes:** concurrent attempts used to read the same counter (Playwright found it by typing wrong PINs fast; the 5th did not trigger the wait) → attempts queue one at a time + the pad is disabled while checking; the countdown interval stops at 0; Forgot is disabled during a wait; stable unlock callback; biometric failures are logged and a manual "Usar huella" failure says so.
- **Declined:** cross-tab race on the counter (one phone, one PWA window); merging the initial-load effect with `refresh()` (React's set-state-in-effect rule forbids it).
- **Trade-off / honest limit:** this is an interface gate against casual looks and the app-switcher, NOT encryption: IndexedDB is plaintext, a 4-digit PIN is brute-forceable offline against the stored hash, and "Olvidé mi PIN" (Piero's choice) lets anyone holding the unlocked phone replace it. The wait after 5 failures only slows the on-screen guesser. Fingerprint is client-side only (no server to check a signature): a passed verification just unlocks, like the PIN.
- **Gotcha:** every earlier Playwright script now meets the PIN screen — create a PIN first (`1,2,3,4` twice). The virtual authenticator (CDP `WebAuthn.addVirtualAuthenticator`, internal + user verifying) proves the code path (enroll, auto-prompt, unverified → PIN) but NOT that Piero's Android and Chrome expose a platform authenticator to an installed PWA: that is the real spike and must be run on his phone (card text says "Huella disponible" or "no disponible"; the outcome is stored as `biometricSpike`).
- **GV:** no board for the lock screen; it reuses the Captura keypad and tokens (no default shadows, targets ≥44 px).

## 2026-10-16 — H7 Cierre del día + racha + nivel
- **Qué:** Inicio gets the "Cierra el día" card (amber "Cerrar" → "Día cerrado" once done) and a flame chip "N días" while the streak is alive; `#/cerrar` = "¿Falta algo?" (today's list, shortcuts "Anotar un gasto" / "Confirmar un ingreso", then "Cerrar el día"); Semana gets the streak card ("N días cerrados de M · racha viva · se rompe si pasan 3 días sin cerrar", "Nivel L"). Closed days go in the export JSON.
- **Por qué:** spec H7 / AC6 / eval 7. Piero's calls (2026-10-16): only today can be closed; streak = closed days of the current run, tolerates 2 passed days, 3rd breaks it; level shown only on the Semana card.
- **Cómo:** pure `domain/streak.ts` (`dayKey`, `streakAt`, `weekCloses`, level = floor(sqrt(closed days))) — it takes closed days only, never amounts or record counts, so the reward cannot depend on spending. New Dexie v2 table `closes` (`day` PK, `closedAt`), additive; `closeToday` derives the day from `now`, never from the caller, and is idempotent. A day in progress never counts as missed (3 days "passed" = 3 days strictly between the last close and today). Forms opened from the close screen return to it (`lastList`).
- **Review fixes:** if the screen was opened before midnight and "Cerrar el día" is tapped after it, nothing is closed (the list was for the old day): a note asks to review and tap again (Playwright: first tap → `closes` empty, second → the new day). `weekCloses.elapsed` never below 1.
- **Declined (with reason):** level formula is Piero's explicit placeholder (spec decision 5); `close` in `lastList` is fine because closing replaces the route with `home`; no restore path exists in v1 (export only); the second live query is negligible at this scale.
- **Trade-off:** a forgotten day can never be closed later (Piero's choice: no incentive to backfill). Streak history lives only in this phone's IndexedDB (like the rest, backed up by the export). The export schema_version stays 1: `closed_days` is an additive field.
- **Gotcha:** `streakAt([] …)` is 0/not alive; once broken it reads 0 but `totalClosed`/level keep counting (level never drops). Streak card placement follows the board (after the Sunday card). Playwright can move the day with `clock.setFixedTime` + reload; RTK's bash filter breaks long heredocs, so test scripts go through the Write tool.
- **GV (VA-1):** PASS vs Main + Semana boards at 390×844: card order, amber outlined "Cerrar", gold flame chip and streak card, tokens, all targets ≥44 px. Deviations: the board's chip is always visible, ours only while the streak is alive (no "0 días" guilt); closed state replaces the button with a calm line; the "¿Falta algo?" screen has no board (it follows the Captura layout).

## 2026-10-16 — H9 Exportar todo (moved ahead of H5) + weekly reminder
- **Qué:** one tap → `platita-export-YYYY-MM-DD.json` + `.csv` to Downloads; optional "Compartir" (Web Share with files) to Drive/WhatsApp/an LLM app; weekly reminder card on Inicio ("Respalda tus datos · Último respaldo: …") when never exported or ≥7 calendar days (Lima). - **Trade-off:** the browser gives no signal if Chrome blocks the second download, so the success message tells Piero to check both files and accept "multiple downloads" if asked (review finding, mitigated not solved). Day counts are calendar days in Lima and clamp a few-seconds-ahead export to "hoy"; an export dated >1 day in the future (wrong phone clock) makes the reminder due again.

## 2026-10-15 — H2 money engine (pure functions)
- **Qué:** `src/domain/time.ts` (ISO weeks in the configured IANA zone via Intl), `flow.ts` (`weeklyNet`, `closedWeeks`, `balanceAt`), `expected.ts` (recurring templates → instances, `expectedStatus`, `confirmExpected`, `ifExpectedArrives`). Evals 2–6 in `money.eval.test.ts`.
- **Por qué:** spec H2 / AC2–AC5. Spec fix first: mesada window = Mon–Thu (eval 6 wins over "window = the week"; Piero, 2026-10-15).
- **Cómo:** **Savings is derived, not accumulated**: savings at week start = opening + Σ weekly_net of all earlier weeks; Sunday close = `closedWeeks()` up to now. Code review found the accumulated design (persisted `lastClosedWeekId`) silently lost movements backdated into, or undone after, a closed week; derived = each movement counts exactly once by construction, and reconcile-on-open is just recomputation. Confirmations are income movements with `recurringId = "<templateId>:<periodKey>"`, so movements stay the single source of truth and generation is idempotent. Movements before `openingBalanceAt` never count (already inside S/230.84). Over-payment of an expected item is allowed (variable amounts); 0/negative/fractional is rejected.
- **Trade-off:** recomputes from all movements each call (fine at personal scale; revisit if open feels slow). `generateExpected` re-walks every period since `activeFrom` and returns settled history (review #6, skipped: ~90 items/year). Changing the timezone setting (H5) re-attributes boundary movements to different weeks in history — totals stay correct, history shifts.
- **Gotcha:** `startOfCivilDay` handles zones where DST skips midnight (verified: America/Santiago 2026-09-06, Havana 03-08, Beirut 03-29 start at 01:00). Stored `Movement.weekId` is a snapshot the engine never reads — export (H9) must recompute it from occurredAt + tz. `ExpectedItem.templateId` is nullable on purpose for one-off "Esperado" items (H4). With W42 opening on Thu 14:31, a mesada template active from opening generates a W42 instance — set `activeFrom` deliberately in H4. `npm test` excludes `*.eval.test.ts` (CI = unit only); evals via `npm run test:evals`. RTK's vitest filter can write `.vitest/` reports (gitignored); use `rtk proxy` for verbose runs.
